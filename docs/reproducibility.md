# 무엇을 다시 확인할 수 있나요?

[처음으로](../README.md) · [노트북 안내](../notebooks/README.md) · [근거와 빠진 자료](evidence.md)

이 저장소는 연구의 코드, 남아 있는 텍스트 출력, 보고서의 기록값을 공개한 포트폴리오입니다. **보고서 값으로 표와 그래프를 다시 만드는 일은 할 수 있지만, 현재 공개 파일만으로 모델을 학습하고 같은 test 예측을 다시 계산할 수는 없습니다.** 2026년 11월 26일 공개 정리 과정에서도 재학습과 새 성능 측정은 하지 않았습니다.

## 결과를 읽고 그래프를 다시 그리기

[CPU 결과 읽기 노트북](../notebooks/00_read_results.ipynb)은 [2026년 9월 21일자 연구보고서](../reports/research-report.pdf)에 기록된 집계값을 사용합니다. GPU, 원본 사진, 비공개 클라우드 계정 없이 실행하는 용도입니다. 표와 그래프가 어디에서 나왔는지 확인하고, 초기 모델과 개선 모델의 지표 차이를 계산할 수 있습니다.

여기에 들어 있는 숫자는 원시 예측 파일을 다시 집계한 값이 아닙니다. 원시 예측·잔차 Parquet 파일을 확보하지 못했으므로, 새 표본별 오차 분석이나 신뢰구간 계산을 이 공개 자료만으로 독립 수행할 수 없습니다. 그래프 재생성과 모델 평가 재현을 구분해 주세요.

## 연구 노트북으로 확인할 수 있는 부분

공개한 원본 유래 노트북 11개에는 데이터 검사, 분할, 학습, 모델 선택과 평가 코드가 있습니다. 내장 이미지 출력을 제거한 뒤에도 수치와 완료 상태 같은 텍스트 출력은 남겼습니다. 현재 남은 코드가 어떤 절차를 구현하는지, 저장 출력에서 무엇을 확인했는지 읽을 수 있습니다. 공개용 파일명과 원래 파일명의 대응은 [노트북 목록](../notebooks/README.md)에 있습니다.

예를 들어 최종 평가 노트북의 출력은 평가 완료와 RMSE 0.14233391569554288 m를 기록합니다. 그러나 이 출력만으로 현재 모든 체크포인트와 예측 파일을 확보했다거나 전체 연구 경로를 다시 실행했다고 말하지 않습니다. 코드, 저장 출력, 실제 산출물은 서로 다른 근거입니다.

## 전체 실행에 필요한 자료와 남은 공백

| 필요한 것 | 공개본 상태와 재현에 미치는 영향 |
| --- | --- |
| AI-Hub Training 원본 이미지·JSON | 저장소에 배포하지 않음. 사용 가능한 원본을 별도로 준비해야 함 |
| 본인 GCS 프로젝트, 저장 경로, 인증 | 공개본은 자리표시자 사용. 원래 비공개 저장소의 접근 권한을 제공하지 않음 |
| 감사 보정 단계 01R | 노트북 미확보. 다음 분할 단계가 요구하는 입력을 처음부터 재생성하는 연결이 끊겨 있음 |
| 초기 세 CNN의 pilot 원시 결과 | 보고서에 비교 수치는 있으나 해당 원시 결과 파일 미확보. 현재 비교 노트북의 학습 결과 출력은 전체 학습한 ConvNeXt만 남아 있음 |
| ROI 전체 학습 실행의 연결 | ROI 코드 설정은 `full-v1`, 뒤의 모델 선택은 `router-full-v2` 참조. 정확히 대응하는 실행 코드·산출물 확인 필요 |
| 최종 재분할의 원시 목록과 완료 파일 | 실제 자료 실행의 저장 출력은 목적함수 20.466860→8.074058, 수락 교환 2,736회로 보고서와 일치. 원시 분할 목록과 seal 파일은 미확보여서 표본별 독립 재검사는 하지 못함 |
| 초기 모델의 평가용 03F | 별도 회수한 코드에는 저장 출력이 없음. 완료 증거를 대신하지 못함 |
| 학습 체크포인트, 원시 예측·잔차 Parquet | 로컬 공개 묶음에 없음. 원래 가중치 추론과 표본별 재집계 불가 |
| 최종 발표 자료 | 내보낸 최종 발표 파일 미확보. 연구보고서 PDF와 구분 |

원래 실행은 원본 ZIP을 보관하고 목록 파일과 tar 이미지 묶음으로 학습을 반복하는 구조였습니다. 같은 이미지 SHA-256 그룹, 분할 수량, 입력 파일 검사값과 완료 파일도 이어져야 합니다. 따라서 데이터만 비슷한 위치에 복사하는 것보다 더 많은 복구가 필요합니다. 구체적인 실행 환경과 순서는 [Colab 안내](colab-guide.md)에 정리했습니다.

환경 확인 노트북의 현재 저장 실행도 엄격한 이미지 읽기 오류에서 중단되었습니다. 반대로 일부 자료 이름에는 `pilot`이 남아 있어도 현재 설정이 `full`인 경우가 있습니다. 이름이나 셀 실행 번호만으로 실행 규모와 완료 여부를 추정하지 않고 설정, 수량과 저장 출력을 함께 확인합니다.

## 같은 점수가 나와도 주장할 수 있는 범위는 따로 있습니다

초기 모델과 개선 모델의 비교에는 내부 test 30,809장이 고정되어 있습니다. 이 목록은 초기 모델의 오류 분석에 이미 사용했습니다. 추론 시 정답을 입력하지 않고 예측을 먼저 저장하는 절차는 유지했지만, 개발 전 과정에서 보지 않은 외부 평가였다는 뜻은 아닙니다. 장소와 시간을 나눈 새로운 평가가 필요합니다.

또한 개선 모델은 장애물 분포 재조정, 보조학습, 학습 에폭과 ROI 학습 조건 등이 함께 바뀌었습니다. 최종 test RMSE 8.58% 감소는 이 변경 묶음의 관측 결과입니다. 장애물 보조 손실만으로 그 감소가 생겼다고 분리해 주장하지 않습니다. 같은 변경 후 검증 자료에서의 수위 단독·보조학습 비교도 RMSE 이득과 MAE·P95 악화를 함께 보였습니다.

완전한 재현을 위해서는 빠진 노트북과 원시 산출물을 회수하고, 입력·설정·모델·예측의 연결을 검사한 다음 단계별로 실행해야 합니다. 반복 학습과 새로운 평가 자료에서의 확인은 그다음 검증 과제이며, 이 공개본에서 완료한 결과에 포함하지 않았습니다.
