# Colab 노트북 읽기와 실행 안내

[처음으로](../README.md) · [노트북 목록과 원래 파일명](../notebooks/README.md) · [재현 범위](reproducibility.md)

처음 보는 분이라면 [CPU 결과 읽기 노트북](../notebooks/00_read_results.ipynb)부터 시작해 주세요. 보고서에 기록된 값을 읽어 표와 그래프를 다시 만드는 노트북입니다. 원본 사진, GPU, 클라우드 인증 없이 결과를 살펴볼 수 있습니다. 모델 예측을 다시 생성하거나 성능을 새로 측정하는 실행은 아닙니다.

나머지 노트북은 실제 연구에 사용한 Colab 코드의 공개 사본입니다. 각 노트북의 소개와 남아 있는 텍스트 출력을 먼저 읽으면, 데이터 검사에서 최종 평가까지 무엇을 확인했는지 따라갈 수 있습니다. 원래 이름과 공개용 이름의 대응은 [노트북 목록](../notebooks/README.md)에 있습니다.

## 실제 연구 코드를 실행하려면

원래 파이프라인은 비공개 Google Cloud Storage(GCS)에 원본 ZIP과 산출물을 보관하고 Colab이 필요한 자료만 읽는 구조입니다. Colab의 `/content`는 세션이 끝나면 사라지는 임시 공간이라, 완료한 단계의 결과와 검사값을 클라우드에 저장하도록 만들었습니다. 원본 압축 자료만 약 117.74 GiB이므로 작은 예제 노트북과 준비량이 다릅니다.

1. 필요한 AI-Hub 자료를 본인이 사용할 수 있는 경로에 준비합니다. 공개 저장소는 원본 사진, JSON 묶음, 모델 가중치와 비공개 test 연결표를 제공하지 않습니다.
2. 본인의 클라우드 프로젝트와 버킷을 설정하고 Colab에서 인증합니다. 공개본의 프로젝트·버킷 자리표시자는 실제 접근 가능한 저장소로 바꿔야 합니다. 인증 토큰이나 서비스 계정 키를 노트북에 적어 넣지는 않습니다.
3. 노트북 첫 설정 셀에서 입력 자료 버전, 실행 모드, 실행 식별자와 출력 위치를 확인합니다. `smoke`는 작은 실행으로 연결을 확인하고, `pilot`은 후보 탐색용 일부 학습 자료, `full`은 전체 적격 학습 자료를 뜻합니다. 셋을 같은 완료 결과로 취급하면 안 됩니다.
4. 해당 단계가 요구하는 이전 산출물과 완료 검사 파일을 먼저 확보합니다. 입력 검사가 실패하면 원인과 자료를 확인합니다. 공개본에서 빠진 단계를 건너뛴 채 검사 조건만 통과시키는 것으로 원래 실행을 복원할 수는 없습니다.
5. 모델 학습과 추론은 새 GPU 런타임에서 첫 셀부터 실행합니다. 완료한 상태에서 이어가는 코드는 같은 설정과 저장된 상태를 전제로 합니다. 새 실험은 별도 출력 식별자를 사용해야 기존 결과와 섞이지 않습니다.

코드의 `seal`은 해당 단계의 입력·설정·출력 검사값과 완료 상태를 기록한 파일입니다. 결과가 바뀌었는지 확인하고 다음 단계가 미완성 자료를 읽지 않게 하려는 장치입니다. 다만 공개본에 그 파일의 경로가 남아 있다는 사실만으로 현재 원격 파일에 접근할 수 있거나 내용을 검증했다는 뜻은 아닙니다.

## 지금 한 번에 끝까지 실행할 수 없는 구간

데이터 감사와 분할 사이의 **01R 보정 노트북**이 없습니다. 분할 노트북은 이 단계가 만든 감사 결과를 요구합니다. ROI 노트북의 설정과 모델 선택 노트북이 참조하는 전체 학습 실행도 일치하지 않아, 현재 파일들을 번호순으로 실행하면 같은 최종 결과가 나오는 상태가 아닙니다. 초기 평가용 03F 코드는 별도로 회수했지만 저장 출력이 없으며, 선택적인 과거 코드로 구분합니다. 자세한 차이는 [근거 문서](evidence.md)에 있습니다.

최종 평가 노트북은 `INFERENCE`에서 정답을 읽지 않고 예측을 먼저 저장하고, 새 세션의 `EVALUATION`에서 정답을 붙이는 구조입니다. 현재 남은 출력에는 평가 완료와 RMSE 0.14233391569554288 m가 있습니다. 이 실행 구조와 별개로 같은 내부 test는 이전 오류 분석에 이미 사용했으므로, 새로운 미사용 외부 평가로 해석하지 않습니다.

## 저장된 출력은 어떻게 남겼나요?

공개 사본은 수치, 표, 진행 로그 같은 텍스트 출력을 남기고 내장 이미지 데이터는 제거했습니다. 따라서 사진이나 일부 그래프가 출력 칸에서 보이지 않을 수 있습니다. 셀의 `execution_count`가 모두 `null`인 상태에서도 실제 텍스트 출력은 남아 있습니다. 실행 번호의 유무만으로 실행 여부나 전체 완료 여부를 판정하지 않고, 해당 출력과 완료 기록을 함께 확인해야 합니다.
